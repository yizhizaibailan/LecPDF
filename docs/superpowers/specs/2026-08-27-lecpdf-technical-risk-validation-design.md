# LecPDF 技术风险验证与架构完善设计

> 日期：2026-08-27  
> 状态：已完成会话内设计确认，等待书面规格审阅  
> 上游文档：`LecPDF-FRD.md`、`LecPDF-ARCHITECTURE.md`

## 1. 目标

通过官方资料核验和可重复运行的 Windows Electron 最小 PoC，验证 LecPDF v1 的高风险能力，并依据真实结果完善功能需求、引擎边界、数据结构与错误处理设计。

本轮必须保留全部 v1 功能。默认采用开源方案；只有在开源路线无法可靠满足验收标准时，才整理商业 SDK 候选并请求用户批准。未经批准不得下载、试用、接入或采购商业 SDK。

## 2. 已批准决策

1. 验证深度采用“官方资料与源码核验 + 最小可运行 PoC”。
2. 全部 v1 功能均为硬约束，验证失败不能直接删除功能或移到 P2。
3. 技术路线按以下顺序逐级升级：公开 API → 应用层扩展 → fork/patch 开源引擎 → 经批准的商业 SDK。
4. 采用开源优先、逐项设闸的验证方案，不同时铺开商业路线，也不在缺少证据时重新进行全量引擎选型。
5. PoC 是非生产验证代码，但必须保留为可重复运行的技术证据。
6. 商业 SDK 必须位于统一适配器之后，并继续满足本地处理、零遥测与数据不出设备约束。

## 3. 范围

### 3.1 官方资料核验

- 核实 embedpdf v2 与 v3 的发布状态、维护状态、公开 API、插件能力和许可证。
- 核实 epub.js 的 CFI、选区、内容重排、iframe 事件和生命周期接口。
- 核实 Electron 与 Chromium 在打印、Web Speech、CSS/Canvas 渲染及本地资源访问方面的官方能力。
- 查阅对应开源项目的官方仓库源码、发布记录和维护者问题记录；不以二手教程作为关键结论依据。
- 固定验证使用的依赖版本，并在风险报告中记录版本与许可证。

### 3.2 PoC

建立一个共享 Electron 验证壳和四个相互隔离的实验模块：

1. PDF 七类批注与批注合成打印。
2. PDF 智能反色与图片保真。
3. EPUB CFI 选区锚定与文本回找。
4. EPUB TTS 句级高亮与会话控制。

### 3.3 设计完善

- 修订 `ReaderEngine` 的职责边界。
- 完善 PDF 与 EPUB 批注锚点模型。
- 将路径身份改为稳定文档身份。
- 引入操作日志与原子快照，消除“500ms 防抖”和“数据零丢失”的设计冲突。
- 明确能力检查、错误状态、schema 迁移和商业 SDK 审批边界。
- 根据验证结果同步修订 FRD 与架构文档。

## 4. 非目标

- 不在 PoC 中实现完整 LecPDF 产品界面。
- 不把 PoC 代码直接复制为生产实现。
- 不验证 FRD 已明确排除的 OCR、AI、格式转换、云同步和 PDF 内容编辑。
- 不在本轮初始化 Git 仓库。
- 不在用户批准前下载或接入商业 SDK。

## 6. 统一判定规则

每项风险必须给出以下信息：

- 官方文档、源码、发布记录或官方问题记录的证据链接。
- 可重复的运行步骤、固定依赖版本和测试样本。
- 自动检查结果与必要的人工复核记录。
- `原生支持`、`应用层扩展`、`需要 fork` 或 `开源不可行` 四选一结论。
- 性能、许可证、维护成本和平台限制。
- 对 v1 验收标准、引擎接口、数据模型和交付排期的影响。

只有结论为 `开源不可行` 时，才可形成商业 SDK 候选清单。候选清单必须说明开源失败证据、所需能力、许可证模式、预估成本、离线与遥测约束，再等待用户批准。

## 7. PoC 验收标准

### 7.1 PDF 七类批注与打印

- 高亮、下划线、删除线、波浪线、便签、自由文本和手绘均可创建、修改、删除并从 sidecar 恢复。
- 缩放、页面旋转以及单页/连续布局切换后，批注几何位置仍与原内容对齐。
- 打印支持“仅原文”和“原文 + 批注”两种模式。
- 带批注打印至少覆盖文本标记、便签、自由文本和手绘，并在生成的打印输出中保持页码、裁剪区域和坐标一致。
- 原 PDF 不被修改；加密 PDF 继续使用 sidecar，密码仅保留在会话内。
- 验证结果必须区分引擎原生批注、应用自绘覆盖层和打印合成层，不得把仅可视的 DOM 演示误判为可打印支持。

### 7.2 PDF 智能反色

测试样本至少包括文本型、扫描型和图文混排 PDF：

- 页面背景转暗，正文文本对比度目标不低于 4.5:1。
- 照片与扫描图不能整体变为负片。
- 高亮及其他批注在暗色背景上保持可辨识。
- 验证公开 API 是否能区分文字、矢量图形、位图和批注层。
- 若公开 API 不提供内容层控制，继续验证自定义渲染插件或 fork 路线，而不是把全页面 CSS 反色判定为“智能反色完成”。

### 7.3 EPUB 批注锚定

- 覆盖中文、英文、跨行和跨内联标签选区。
- 重新打开书籍、改变字号/行距/页边距、改变窗口尺寸以及分页/滚动布局切换后，原 CFI 可恢复。
- 未改变内容的 EPUB 锚点恢复率必须为 100%。
- CFI 失效后，使用 `exact quote + prefix + suffix` 回找。
- 唯一匹配时可自动重定位；多匹配或无匹配时标记 `orphaned` 并等待人工重定位，禁止静默跳到错误位置。

### 7.4 EPUB TTS 句级高亮

- 中英文内容均支持播放、暂停、继续、停止和跨段落推进。
- 高亮始终对应当前朗读句，章节切换后可继续工作。
- 音色来自操作系统已安装语音；产品不承诺不同设备具有相同音色。
- 验证 Electron 中 iframe、Web Speech 边界事件、epub.js 重排和章节切换行为。
- 若系统边界事件不足以稳定驱动高亮，继续验证“本地分句 + 句子队列 + 逐句朗读”方案。

### 7.5 共同约束

- PoC 必须在 Windows Electron 环境中运行，不能仅在普通浏览器中演示。
- 运行过程保持离线、零遥测，测试内容不得上传。
- 每项同时包含自动检查与明确列出的人工复核步骤。
- 测试样本必须自生成或具有允许再分发的开放许可证。

## 8. 架构修订方向

### 8.1 引擎能力拆分

将现有大而全的 `ReaderEngine` 拆为核心生命周期与独立能力模块：

- `DocumentEngine`：打开、关闭、导航、布局和位置恢复。
- `AnnotationEngine`：批注创建、更新、删除、序列化和恢复。
- `PrintComposer`：原页面与批注层合成，独立于屏幕阅读视口。
- `NightModeRenderer`：PDF 内容感知反色与批注对比度保护。
- `AnchorResolver`：EPUB CFI、文本引用及失效重定位。
- `TtsSession`：分句、朗读队列、高亮和会话状态。
- `EngineCapabilities`：报告当前实现、版本和实际能力。

发布构建必须通过全部 v1 能力检查。缺失能力应让发布检查失败，不得在生产环境静默隐藏 v1 功能。

### 8.2 批注锚点与几何模型

- EPUB 锚点保存 CFI、精确文本、前缀和后缀，不再只保存 `epubCfi + quote`。
- PDF 文本标记保存标准化四边形集合，而不是只保存轴对齐矩形。
- 便签保存页面点坐标；自由文本保存矩形、字体和样式；手绘保存路径、线宽和透明度。
- 所有坐标均明确页面坐标系、旋转基准和归一化规则。
- 失效锚点使用显式 `orphaned` 状态，数据不得被自动删除。

### 8.3 文档身份

- 每个文档首次进入库时生成稳定 `documentId`，sidecar 文件名使用 `documentId`。
- 规范化路径是当前位置索引，不再是永久主键。
- 保存轻量文件指纹，用于文件移动后的候选匹配；匹配成功后更新路径映射，不改变 `documentId`。
- 指纹冲突或多个候选同时匹配时必须要求用户确认。

### 8.4 持久化与崩溃恢复

- 用户操作先追加到轻量操作日志。
- 内存态更新后，以 500ms 防抖生成完整 sidecar 原子快照。
- 快照成功落盘后，清理已包含在快照中的日志记录。
- 异常退出后先加载最后快照，再重放未合并日志。
- 所有磁盘 schema 具有明确版本号和逐版本迁移器。
- 遇到未知高版本 schema 时进入只读保护，不覆盖用户数据。

## 9. 错误处理

- 文件不存在：保留库记录并进入重定位流程。
- 锚点无法唯一恢复：标记 `orphaned`，展示原摘录和重定位入口。
- 批注打印合成失败：中止“含批注打印”，保留仅原文打印选项并记录本地错误；发布前该失败必须解决，不能作为 v1 永久降级。
- TTS 语音不可用：提示安装系统语音包；不将文本发送到云端。
- 操作日志损坏：隔离损坏尾部、恢复可解析记录，并保留原文件供诊断。
- 引擎能力不完整：开发/CI 能力检查失败并阻止发布。

## 10. 测试策略

- 单元测试：锚点序列化、文本回找、坐标转换、能力判定、操作日志重放和 schema 迁移。
- Electron 集成测试：四个实验模块的打开、操作、重载和状态恢复。
- 输出检查：对批注打印结果进行页面数、尺寸和关键坐标检查。
- 视觉复核：PDF 批注对齐、暗色模式图像保真和批注对比度。
- 听觉/状态复核：TTS 句子推进、暂停恢复和章节切换。
- 许可证检查：记录直接依赖和为 PoC 引入的间接核心依赖许可证。

## 15. 实施计划拆分

本规格是风险验证的总设计，不应生成一个覆盖所有实验的巨型实施计划。书面规格获批后，实施阶段拆为六个可独立验收的计划：

1. 官方资料核验、依赖锁定、共享 Electron 测试壳与 fixtures。
2. PDF 七类批注与批注合成打印。
3. PDF 智能反色与图片保真。
4. EPUB CFI 锚定与文本回找。
5. EPUB TTS 句级高亮与会话控制。
6. 风险报告、FRD 与架构文档的结果汇总和一致性修订。

计划 2–5 均依赖计划 1，但彼此之间不共享实验实现。计划 6 在四个实验产生结论后执行。是否采用子代理或当前会话顺序执行，由用户在实施计划完成后选择；本规格不预先授权并行代理工作。
